# 词库成体系 · 纠错体检（2026-11-10）

用户原话：「优化输入法，尤其是词库方面。词库现在很不系统，比如说地名、国家名等等。自动联想诗句。」
追加：「你吃点饭了？」总是打成别的；「反正就是纠错也有问题」。

环境：Linux arm64 sandbox，librime 1.13.1 + librime-lua，雾凇 nightly full.zip（与 CI 的 rime_test 相同），未真机验证。

## 1. 「你吃点饭了」

| 条件 | nichidianfanle 首选 |
|---|---|
| 无语法模型（默认安装） | 你吃**典范**了 ✗ |
| 无模型 + 模糊音 n=l | **里词典犯了** ✗ |
| 万象语法模型 | 你吃点饭了 ✓ |
| 语法模型，少打 dian 且 le 打成 li（nichifanli） | 你吃饭**里** ✗（与用户描述的「你吃饭里」一致的唯一复现） |
| 纠错开/关、个人纠错规则 | 无影响（整句 > 12 个字母，纠错不触发） |
| **修复后**（无模型 / 有模型） | 你吃点饭了 ✓ / ✓ |

根因：没有语法模型时 librime 只按词频拼句子。雾凇 base 里「典范」101150、「犯了」75830，而「吃点饭」只在腾讯词库里、权重统一是 100，
所以「你吃 + 典范 + 了」压过了「你 + 吃点饭 + 了」。用户截图里的「你吃饭里」在本机没能用完整拼音复现（模糊音 n=l 会把 ni 变成「里」，
有模型时 nichifanli 正好出「你吃饭里」），如果仍然出现，请用「生成维护报告」带上设置摘要，重点看是否开了 n=l 模糊音、是否装了语法模型、用户词库里有没有学进「饭里」。
修复：口语短句词库（吃点饭、喝点水、到哪了……，校准到 base 同长度 75 分位），同类口语句（你吃了吗、我先走了、你到哪了、吃点东西、喝点水吧）全部首选正确。

## 2. 纠错体检

2000 句语料（全部是正确拼音）在纠错开/关、「可排第一」开时各跑一遍，比较首选与前 3：

| | 纠错候选出现在正确输入上（误纠） | 首选被改坏 |
|---|---|---|
| 收紧前，默认（第 2 位起） | 20 句（1.00%） | 0 |
| 收紧前，「可排第一」 | 20 句 | **13 句**（他住了→他输了、都过期了→都过去了、名声的→明正德…） |
| 收紧后，默认 | **4 句（0.20%）** | 0 |
| 收紧后，「可排第一」 | 4 句 | **0** |

根因：纠错触发条件只看「前 8 个候选里有没有整段的词」，正确的短句（tazhule、douguoqile）本来就拼不出整词，于是被当成打错。
收紧：输入能完整切成 3 个以上正常音节（不靠单独的 a/e/o 凑）时当句子，不纠；1–2 个音节（yinggua）照纠。
该纠没纠（400 个常用词随机打错一个字母）：纠错关 18.3% → 收紧前 69.5% → 收紧后 66.3%（前 3 命中）；损失的是「打错后恰好仍是 3 个合法音节」的情况，按用户要求以少误纠优先。
librime 自带 enable_correction 仍然不开（11-06 实测会把 nihao 首选改成「你是」）。
